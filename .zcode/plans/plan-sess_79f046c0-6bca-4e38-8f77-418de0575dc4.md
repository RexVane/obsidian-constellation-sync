# 改用 GitHub Token(PAT)登录,彻底移除 GitHub App

## 目标体验

点"创建令牌" → 浏览器打开 GitHub 令牌创建页(已预填名称和 `repo` 权限)→ 点 Generate → 复制 → 粘贴回插件 → 完成。**一次浏览器访问、零输入验证码、你不需要配置任何 GitHub App**。插件端无任何 secret。

## 认证流程(新)

- 用户粘贴令牌(经典 `ghp_...` 或细粒度 `github_pat_...` 均可)→ 插件调 `GET /user` 验证 → 存入 SecretStorage(格式 `{accessToken, tokenType:"pat"}`,无过期时间)。
- 现有 `getValidAccessToken()` 对无 `expiresAt` 的会话本就原样返回令牌——PAT 会话几乎零成本接入,所有 API 调用(`Bearer` 头)、仓库发现、同步逻辑全部不变。
- 仓库发现从 App 专属的 `/user/installations` 接口改为 `GET /user/repos?visibility=private&per_page=100` 分页;细粒度令牌天然只返回其被授权的仓库,正好符合最小授权。

## 移除(干净切掉,不做双轨)

- 设备流全套:`beginDeviceFlow` / `pollDeviceFlow` / `refresh()`(PAT 无刷新概念)/ `loginAbort` / `DeviceCode` 类型 / 设备码 UI 面板。
- App 构建配置:`__GITHUB_CLIENT_ID__ / __GITHUB_APP_SLUG__ / __GITHUB_INSTALL_URL__` 三个注入、`.env.example` 文件、release workflow 里的对应 env、`GitHubAppConfig`、`snapshot.githubConfigured / appInstallUrl`、设置页"安装 App"按钮、"GitHub App: configured" 诊断项。
- 旧 App 会话兼容:已连接用户的存量令牌仍能用到过期;过期后走现有 `reauth-required` 状态,提示用令牌重新登录(CHANGELOG 注明破坏性变更 0.2.0)。

## 新增

- `GitHubAuth.setPatSession(token)`:trim 后直接持久化;过期分支简化为"令牌失效,请重新连接"。
- `controller` 接口 `startLogin/cancelLogin` → `connectWithToken(token)`,由 main 实现并借 `github.getAccount()` 完成验证与账号拉取。
- 登录面板:令牌粘贴框 + "创建令牌"按钮(经典令牌预填链接 `github.com/settings/tokens/new?description=Constellation%20Sync&scopes=repo`)+ 细粒度令牌的最小权限指引(仅选中仓库 + Contents 读写,建议长有效期);连接后仓库列表为空时给出"令牌未授权任何仓库"的提示文案。
- 中英文 i18n 各增删约 10 个 key。

## 边界处理

- 令牌权限不足:连接成功但列不到仓库 → 空态提示 + 指引,不报错卡死。
- 令牌过期(用户选了短期):现有 `reauth-required` 状态机路径直接复用,UI 提示重新粘贴。
- 移动端:粘贴令牌全平台一致,`isDesktopOnly` 保持 false。
- 公开仓库拒绝逻辑、限流处理、同步引擎全部不动。
